## 1. User research (design:user-research)

This is desk research only. No interviews or usability tests were run, so treat each line below as a hypothesis to test.

Each studio's people and needs come from its closest iPad reference above.

| Studio | Who on iPad | Shortcut need | Copy need |
|---|---|---|---|
| Quill (Word) | Writers and students with a Magic Keyboard | ⌘Z, ⌘S and ⌘O must behave as in Word and Pages. ⌘Z inside the text must undo typing, not the document. | Name paragraphs, not block kinds. Say what an empty paragraph is. |
| Tally (Excel) | Analysts who use the keyboard all the time | The same set. Ctrl+Y redo for people coming from Windows. | "Filled cells", not "cells". Name a formula action by its result. |
| Pitch (PowerPoint) | Presenters editing on the go | Undo and save | Slide numbers from 1. A blank slide says how to add a title. |
| Prism (Photoshop, Illustrator, Affinity) | Illustrators and designers, often pencil plus keyboard | ⌘Z with ⇧⌘Z is muscle memory. A held ⌘Z must keep undoing. | Layer numbers from 1, opacity in %, no compositing jargon. |
| Cadence (Logic Pro) | Producers sketching ideas | Undo and redo while arranging | Beats, not ticks. "Add C major chord", not "C-major clip". |
| Splice and Motion (Premiere, Procreate Dreams) | Editors and animators | Undo and redo while trimming | Frame rate in fps, a "Muted" or "Hidden" state, no "rect" or "t=1". |
| Photo (Lightroom) | Photographers culling on the couch | Undo and redo | Photos and edits, not originals, versions or bytes. |
| Design (Figma) and Draft (CAD) | Product designers and makers | Undo, redo and save | Elements, not nodes. Lines, not segments. Units in words. |
| Folio (PDF) | Reviewers annotating | Undo and save | Pages and notes. Drop "semantic document projection". |

**Themes**

- **Pros expect the desktop shortcuts on an iPad keyboard.** Apple's HIG keyboard guidance is that standard shortcuts such as ⌘Z and ⌘S should behave as they do everywhere, and every reference above supports them.
- **Copy should use the person's nouns**: photo, slide, layer, beat. Engine nouns (snapshot, projection, bytes, ticks) are invisible to them.
- **A shortcut is only learnable if it is visible.** The references show it in a help sheet and in the control's name.

## 5. Critique (design:design-critique)

**Overall.** The chrome now meets AA throughout, and the copy now reads like a pro app rather than a test harness. The biggest remaining gap is that nothing here has run on a real iPad with a keyboard.

| Finding | Severity | Recommendation |
|---|---|---|
| Shortcuts are only discoverable through the menu or ⌘/. iPadOS shows the app's shortcuts when ⌘ is held. | 🟡 Moderate | Add the native `UIKeyCommand` discoverability list when the iOS host shell lands. The web sheet matches [VEED](https://mobbin.com/screens/a3215c97-9eca-4514-a3b5-d414c2cfc6a0) and [Luma](https://mobbin.com/screens/9e5d49cd-4b38-4e5c-b793-80cceef7642e) in the meantime. |
| The example app has no Open, so ⌘O does nothing there and is left to the platform. | 🟢 Minor | Wire `onOpen` when the example gains a document picker. The sheet hides the Open row when it has no handler. |
| The empty states reuse the `APP_MANIFESTS` task text, so they're accurate but generic. They do follow the Reddit and CapCut pattern: what this is, then one action. | 🟢 Minor | Write a per-studio first action ("Add your first slide") once each studio has a real create flow. |
| `controlBorder` makes edges visibly heavier in the light palettes. That is intended for inputs, but dividers keep `line`. | 🟢 Minor | Check density screenshots in the next QA capture. |
| The document stage still has hardcoded paper colours (#798373, #66735f), which are outside this audit's scope. | 🟡 Moderate | Move them to `paperMuted` and `paperInk` in a follow-up, and add them to the contrast test. |

**What works**

- One set of panel names.
- 1-indexed labels.
- The sentence-case "Panel position" matches [Subframe's inspector](https://mobbin.com/screens/3869ef7f-13c6-4257-950c-b028ac2bc028).
- The token-level contrast fix means every studio and density inherits it.

## 7. Code review (engineering:code-review)

I reviewed the branch diff against `a067399`. I fixed what I found and list it below.

- **Fixed: Open must not run through `perform()`.** `perform` holds `operation.current` until its promise settles. A file chooser that the person closes without choosing never settles in some browsers, which would have locked Undo and Save. Open now calls the host directly and reports errors to the store.
- **Fixed: `FilePicker` drops `aria-label`.** I checked the NYC-Tron `FilePicker.web.js` source. Open carries the shortcut through `accessibilityHint` instead, which it does forward.
- **Fixed: `exactOptionalPropertyTypes`.** The key-event fields are typed `| undefined` so React Native's `nativeEvent` (`repeat: boolean | undefined`) is assignable.
- **Fixed: one key, one undo.** The ink toolbar (`editor-controls` `ink-model.ts`) and the spreadsheet grid handle their own ⌘ keys and call `preventDefault`. The workspace layer now ignores an event that is already `defaultPrevented`, so a ⌘Z in the ink toolbar undoes one ink stroke, not the stroke and the document.
- **Fixed: no listener leak.** The document listener is added once per mount and removed on unmount. Handlers are read through a ref, so later renders never re-register it.
- **Security.** Nothing here is a concern: no new network access, no `eval`, and the hidden file input only reads a file the person chooses.
- **Performance.** Each keydown makes one `getClientRects` call, but only while a studio is mounted.
- **Residual risk 1.** `isApplePlatform` relies on `navigator.platform`, which is deprecated. iPadOS Safari reports "MacIntel", so it still resolves to ⌘. The user-agent fallback covers browsers that drop `platform`.
- **Residual risk 2.** The workspace source tests are regex checks of `index.tsx`, because node strip-types can't import `.tsx`. They'll need updating if the wiring is renamed.
- **Residual risk 3.** As the brief asks, every shortcut is ignored while the person types in a field, ⌘S included. In Quill's text field, ⌘S therefore reaches the browser, which offers to save the web page. Quill already asks people to apply text changes before saving. If ⌘S should save from inside the field, that needs a product decision, not just a key change.
