# Cadence routing, inserts and MIDI composition

The preview now composes three canonical detail panels: Routing, Effects and MIDI. Their selection lives in a per-document Zustand store. The existing surface owns the document handle, authoritative read state and shared header/editor write gate. No player, audio context, measurement loop or engine session is created here.

Routing uses `CadenceMixerAdapter.routing()` and `mixerClusterRoutes()` with NYC-Tron's BusAndRoutingMatrix. Add bus calls the existing typed `addTrack('bus')` operation. Output, send-level and remove-send intents retain their original promises and reconcile from authoritative project state.

Effects selects a real source track or bus and composes InsertEffectRack, PluginPresetBrowser and PrecisionScrubber. Add, remove, reorder and bypass use the existing adapter. Factory presets load through the selected insert's engine API; no last-applied preset is fabricated. Gain, all compressor parameters and each existing EQ band's type, enabled state, frequency, gain and Q map to bounded engine parameters. EQ edits preserve the other bands from the same source revision. Empty projects offer a real Add MIDI track action.

MIDI selects an existing MIDI track and clip. Empty MIDI tracks offer a real four-bar clip action. MIDIPianoRoll and MIDIVelocityLane share selected note and horizontal scroll. Note add/move/resize/remove, channel changes, individual velocity and atomic velocity ramps use existing typed bindings. Measure lines use the signature’s quarter-note count, so 6/8 correctly spans three quarter notes. The pinned piano roll cannot mark fractional-quarter bar boundaries (for example 5/8); those signatures show a limitation message while tick-based velocity editing remains available. No false bar grid is rendered. Audition is omitted because this preview does not own audio output.

Every write checks the captured document, authoritative project and selected detail identity before entering the parent's admission gate. Changing a detail selection invalidates old callbacks synchronously. The pinned alpha.4 controls lack the newer scope/revision API, so authoritative project, selection and availability boundaries remount their local draft/gesture state. Density and geometry never enter those keys; app selection stays in the store above them. This prioritizes cancellation over preserving widget-local focus/scroll across edits; native keyboard and scroll restoration still need acceptance. The alpha.4 piano roll has uncontrolled horizontal scrolling and resets to zero on an authority remount. The velocity lane also receives zero until the newly mounted piano roll reports its own scroll offset for that exact control boundary; old scroll events cannot acknowledge a new boundary. This preserves alignment, not the previous horizontal anchor. Preset reads publish only when the document, project, insert selection and enabled state still match; stale or disabled results are discarded. Legacy void callback paths get a rejection observer while awaited callers receive the original promise.

Focused static verification: studio-preview TypeScript and whitespace checks passed. Numeric gain, compressor and EQ ranges were compared with `packages/cadence/rust/src/mixer_model.rs` validation. Runtime, source/browser/native suites and production engine scenarios remain deferred to the user's component-review gate. Previous phase evidence does not certify these new panels. The public alpha.4 pin remains unchanged; comfortable scrubber internals use the new canonical target extension only when the pending NYC-Tron source/release is supplied.

Remaining work includes measured EQ/dynamics graphs, live meters, native audio playback/routing, automation-lane composition, audio recording/import/render/export, and native accessibility/performance acceptance. This is document-control composition, not a complete DAW or a playback host.

The parent reads the full CadenceMixerState and uses mixerClusterChannels, so actual bus channels remain compatible with the mixer. Tempo and console receive the workspace target request. Their new nested target behavior depends on NYC-Tron source `48aef26` and a later accepted release; the alpha.4 pin is preserved. No new browser/native/runtime execution is claimed by this checkpoint.

The existing mixer also binds solo-safe and group mute/solo through CadenceMixerAdapter. Its legacy void callbacks observe rejections while awaited controls receive the original promise. The final preview typecheck and static production build passed. The build retains chunk-size, RN Web directive and future config-loader warnings; it does not establish runtime or performance acceptance.
