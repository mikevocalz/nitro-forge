# Pitch boundary sections: source slice

2026-11-07. Pitch now persists `sections:[{id,label,start_slide_id}]` and a separate monotonic `next_section_id`. Both fields have defaults for older snapshots: no sections and counter 1. Section identity is independent of slide/object identity and never changes during rename or boundary reassignment.

`addSection {label,start_slide}` creates a boundary. `updateSection {id,label?,start_slide?}` renames or moves that boundary to a different existing slide. `removeSection {id}` removes only the boundary, retaining every slide. A boundary follows its start slide through deck reordering. Single/bulk deletion of its start slide removes the boundary in the same undoable operation; it does not silently reassign that boundary to another slide. Undo restores the prior boundaries and slides together.

Validation requires at most 1024 sections, distinct positive safe-integer section IDs below the next counter, distinct existing start slides, nonblank labels at most 1024 UTF-8 bytes and a next counter within the host safe-integer range. Add/update fully stage and validate before journal/state mutation. Equal/empty updates do not consume identities, emit events or clear redo. Unknown sections, duplicate starts and invalid labels/references reject atomically. Restore validates the new section identities/counter/labels/references before replacing the document or its history.

The typed document exposes these actual operations. `readPitchDeck` returns validated authoritative boundary metadata as `{id,label,startSlideId}` strings for host use, defaulting old snapshots to an empty list. The pinned alpha.4 SlideFilmstrip/SlideSorter declarations have no section props or mutation callbacks; no unsupported props, local section stand-ins or default UI activation were added. Newer Tron source has read-only filmstrip section headers, which remains a separate release/adoption step.

Executed checks: the full affected Pitch Rust suite passed 25 tests, including the 2 section lifecycle/legacy/corrupt-restore tests; the Pitch office adapter file passed 11 tests, including new metadata defaults/mapping/rejection cases. Pitch direct TypeScript checking, `cargo check -p pitch-engine --tests` and static diff checking passed. No native, broad engine suite, application rollout or complete P14 acceptance is claimed. The Pitch ENGINE_OPS section now documents the schema, operations, budgets and deletion semantics after coordination with the Quill owner. STATUS remains unchanged.
