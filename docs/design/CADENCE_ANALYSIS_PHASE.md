# Cadence automation, curves and offline analysis

This source phase adds `CadenceAnalysisControls` to the existing preview composition. It receives the already-open document, authoritative CadenceMixerState, current disabled state and the parent's mutation admission gate. Its Automation, EQ/dynamics and Offline analysis tabs use NYC-Tron's canonical controls. Per-document selection uses Zustand; document handles and read generations stay outside serialized application state.

Automation exposes the engine's Off and Read modes, plus gain/pan point add, move and remove through CadenceMixerAdapter. The visible window is explicitly the first one, four or eight bars, with a 2048-point preview limit. The subset retains original engine indices for writes. The pinned lane accepts whole-quarter bar grids; fractional-quarter signatures show its limitation while mode selection remains available. Live Write, Touch and Latch recording are not offered. This phase does not imply transport recording.

EQ graphs display the selected insert's actual 128-point response at 48 kHz and committed band parameters. Graph edits use the adapter's fresh read/modify/write binding; enabled changes preserve other bands. Compressor graphs display the actual engine transfer curve and commit threshold/ratio changes. The app does not calculate filter or compressor response, and supplies no synthetic input meter dot.

Offline analysis runs only on request. It measures the first selected bar window, capped at ten seconds and the last clip end, at 48 kHz with the metronome excluded. Loudness and the 32-band/1024-hop spectrogram are requested sequentially to avoid simultaneous render buffers; a synchronous admission flag prevents duplicate requests. The rendered results use LoudnessMeter and SpectrogramView and are labelled as offline master measurements, not live playback. Empty projects offer guidance instead of fabricated data.

Every asynchronous result is bound to the current document, authoritative project, selected panel/track/insert/window and disabled generation. Source or selection changes discard stale results, including failures. New authoritative generations remount older released widget-local drafts and gestures while keeping app selection above them. Mutations preserve their original rejection; legacy void callbacks observe it. Read-only measurements do not use the mutation gate, which would otherwise reload the project and invalidate every measurement. The existing engine worker serializes requests; result admission prevents a measurement from being shown against changed source data. Cancellation discards the reply; the current read API does not abort an engine request already in flight.

Validation: preview TypeScript checking and static diff checking passed. No runtime, browser, native, engine acceptance or full suite was run for this batch, per the user's component-review gate. Prior phase scenarios do not validate these new controls. Native gestures, focus, long text, screen readers, RTL, accessibility scaling and performance remain unverified. Published alpha.4 and consumer pins are unchanged.

Remaining work includes native live measurement/output, recording/import/render/export composition, arbitrary automation windows, fractional-quarter automation grids and cross-device acceptance. These controls do not own an audio context or player, and do not establish a complete DAW.

The parent Analysis tab routes mutations through the parent detail-selection guard before the shared document gate. Synchronous unmount cleanup closes late widget callbacks. Graph selection is filtered against current EQ bands. Final preview typecheck, static production build and independent source review passed; existing bundle/directive/config-loader warnings remain recorded, with no runtime or performance acceptance claim.
