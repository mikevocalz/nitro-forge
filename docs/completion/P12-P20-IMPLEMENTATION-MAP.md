## Concrete backend entry points

- **P12:** [Quill adapter](../../packages/quill/src/office-cluster.ts) now supports direct font family/size, shading, style-preserving case changes and bounded explicit lists/DOCX numbering. Bookmarks, page pixels and the broader document/layout exit remain open. Extend [Quill Rust](../../packages/quill/rust/src/lib.rs) and [DOCX serialization](../../packages/quill/rust/src/docx.rs) together. These listed adapter gaps are a minimum, not the full phase exit.
- **P13:** [Tally adapter](../../packages/tally/src/grid-cluster.ts) supports persistent duplication/reorder/protection/semantic tab tones and bounded view bindings. Persisted charts/sparklines, wider formatting/data operations and the full workbook exit remain open. [Workbook engine](../../packages/tally/rust/src/lib.rs), [formula evaluator](../../packages/tally/rust/src/formula.rs) and [range operations](../../packages/tally/rust/src/range_ops.rs) are the real extension points. Add durable representation before claiming control integration.
- **P14:** [Pitch adapter](../../packages/pitch/src/office-cluster.ts) now supplies persistent sections/slide size/object ordering/text restyling and real animation updates, explicit trigger evaluation and emphasis/exit effects. Pinned controls still lack some authoring callbacks; host presentation, media and rendering acceptance remain open. Extend [Pitch Rust](../../packages/pitch/rust/src/lib.rs), then add actual render/presentation integration. Its current adapter cannot satisfy the whole presentation exit.
- **P15:** [Folio adapter](../../packages/folio/src/office-cluster.ts) now persists comment text, metadata/replies/review state, and bounded Highlight/Underline/StrikeOut plus Square/Circle geometry, while page rendering, glyph positions, ink annotations remain deferred. The pinned thread control still lacks an edit callback. [Folio Rust](../../packages/folio/rust/src/lib.rs) wraps real lopdf documents but explicitly documents lossy text extraction that ignores font encoding and positions. PDF object editing is not a complete renderer, secure redaction implementation or signature workflow.
- **P16/P17:** The new [Design source](reports/P16-design-fixed-frame-source.md) supplies bounded frame trees, row/column wrapping, fixed/hug/fill evaluation and actual Prism pixels with additive engine identity 9. Photo7 and Motion8 are also registered source engines. The [Draft10 source](reports/P17-draft-source.md) now adds bounded 2D points/segments/circles/arcs, analytic snaps, linear point solving and real Prism pixels. Full design/prototype execution and general CAD/3D remain separate backend work; see [entry plan](reports/P16-P17-backend-entry-plan.md). Existing Prism operations do not establish a complete CAD solver, 3D scene renderer or prototype runtime. Native consumer rebuild and product adoption remain required before activating the new source APIs.

## Dependencies and platform gates

P12 requires licensed fonts and native IME/caret/selection/speech integration. P13 requires real keyboard and clipboard semantics plus admitted workbook format support. P14 requires media decode/render and external-display support. P15 needs a chosen rendering/text-position backend with pinned source, license closure and target build support; no PDF dependency is selected or approved by this audit. Redaction must remove sensitive content in saved artifacts, and cryptographic signing must use real keys and trust validation.

P16 requires layout/prototype execution and real collaboration/export services. P17 requires admitted geometry/constraint, renderer and image/baking dependencies with GPU and target support; UI callback contracts do not supply these services. P18 requires SDK/toolchain/device availability for every claimed target, native ownership/lifecycle verification and package ABI checks. Preserve established window dimensions/orientation, Quest configuration, manifest merges and platform navigation contracts throughout.

P19 runtime/native/full-suite acceptance remains after user review. Earlier successful checks cannot be applied to changed source. P20 follows accepted source and actual release artifacts; publishing or updating pins does not close missing functionality. The initial audit performed no installations, builds or tests. Later focused source checks are recorded in the linked checkpoint reports; they do not promote runtime acceptance.
