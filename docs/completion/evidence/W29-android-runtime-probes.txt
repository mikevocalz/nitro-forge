Probe 1 — "Verify native engines" (verify-engines.ts)
-----------------------------------------------------
Result shown in app (accessibility tree) and Metro console:

  engine failures: draft: draft: snapshot round trip changed document
  (describe fields identical except source_revision). Passed: prism, cadence,
  splice, folio, pitch, tally, quill, photo, motion, design. Cadence edit,
  undo, redo and reopen passed.

Reading: for each of the 11 registered kinds the probe ran new -> describe ->
NFD1 snapshot -> restore -> describe equality -> invalid-restore rejection with
state unchanged -> close -> closed-handle rejection. Ten kinds passed all of
it. Draft passed snapshot envelope, invalid-restore atomicity and close, but
its describe output differs after a valid restore ONLY in source_revision:
packages/draft/rust/src/engine.rs restore() intentionally consumes a revision
(next_revision() at ~line 1578) and describe reports source_revision, so the
strict full-JSON equality fails. All document fields are identical. Whether a
revision bump on restore should be reflected in describe is a contract
question for review; it is not silent state loss.
