# P15 saved rectangle and ellipse annotations

Folio now accepts actual Square and Circle annotation subtypes and the existing canonical toolbar rectangle/ellipse tools. Host rectangles remain default PDF user-space [x,y,w,h]. Both dimensions must be positive, all corners within ±1000000 units and distinct/finite in lopdf's f32 representation before any journal/object mutation.

The dictionaries follow ISO32000-1 §12.5.6.8 Table177, inspected in the [Adobe specification](https://opensource.adobe.com/dc-acrobat-sdk-docs/standards/pdfstandards/pdf/PDF32000_2008.pdf); the [primary Apryse API reference](https://sdk.apryse.com/api/PDFTronSDK/java/com/pdftron/pdf/annots/Square.html) describes the same inscribed rectangle/ellipse geometry. Output explicitly uses a solid one-point black DeviceGray border and transparent interior. No text QuadPoints or appearance stream is attached to shapes. Host placement, rotation/crop conversion, configurable styling, renderer integration and cross-viewer visual acceptance are not supplied by this slice.

Independent review caught version compatibility on older imported files. Shape output emits IC (PDF1.4), so an older valid header is raised to1.4; newer headers and catalog metadata are preserved. The change is journaled with the annotation and undo restores the imported header. Unknown header syntax rejects before mutation. Existing comment edit/reply/review remains restricted to Text/Highlight; generic listing/deletion and actual PDF save/reopen work for shapes. Older native engines reject the unsupported subtype before changing their document; no default runtime or pin is activated.
