# P15 rectangle-based PDF text markup source checkpoint

Folio now writes the required QuadPoints for Highlight and accepts actual Underline and StrikeOut PDF annotations. Each operation uses the caller's [x,y,w,h] rectangle in default PDF user space, with one horizontal +X-oriented quad. The engine does not derive text selection, glyph positions, page rotation/crop transforms or multi-line geometry.

The normative source is ISO 32000-1:2008 §12.5.6.10 Table179 and Figure64, published by [Adobe](https://opensource.adobe.com/dc-acrobat-sdk-docs/standards/pdfstandards/pdf/PDF32000_2008.pdf). It defines counterclockwise vertices with the first edge setting text direction. The implementation emits bottom-left, bottom-right, top-right, top-left. A caller must supply a rectangle encompassing the intended contiguous text; the engine cannot verify that relationship without glyph-position support. No appearance stream is fabricated. Primary [Apryse SDK documentation](https://sdk.apryse.com/api/PDFTronSDK/java/com/pdftron/pdf/annots/TextMarkup.html) notes Acrobat's differing point interpretation; this checkpoint follows the normative order and does not claim cross-viewer visual acceptance.

Before journal/object mutation, markup validates positive width/height, all corners within ±1000000 PDF units, and noncollapsed f32-representable corners. All annotation types reject nonfinite f32 endpoints. Creation contents are bounded to 32767 UTF-16 units, matching the existing edit contract. Highlight remains in the existing comment-edit/reply/review subset; Underline/StrikeOut retain generic listing/deletion but do not gain that separate comment contract.

The typed subtype includes both new markup types. The installed alpha.4 canonical AnnotationToolbar explicitly supports underline and strike IDs, so the existing adapter offers those actual operations. Unsupported ink and shape tools remain deferred. No app host, renderer, native module, dependency or release pin changes.

Validation: 29/29 Folio Rust tests pass, including two new regressions across all three markup types. They inspect real dictionaries/QuadPoints, save and reopen actual PDF bytes, restore snapshots, undo/redo and reject degenerate/oversized/overflow geometry while preserving document bytes and redo. All 15 Folio TypeScript tests across six files pass, including actual toolbar subtype forwarding and retained unsupported-tool rejection. Package typecheck and diff checks pass. Visual/native runtime acceptance remains deferred.
