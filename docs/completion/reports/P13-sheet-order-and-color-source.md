# P13 sheet ordering and tab color source

Implemented two previously deferred I-08 operations in the real Tally engine: `moveSheet` uses a final zero-based destination and preserves the active sheet by its internal identity; `setSheetColor` stores the five canonical semantic tab tones or clears with null. Validation happens before mutation. Same-value requests return without events or journal entries, preserving redo history. Changed operations record one existing structural workbook journal entry, giving atomic undo/redo including active selection and cells. Snapshots persist the tone; older snapshots default to none, and invalid snapshot tones fail before replacing the workbook. Engine kinds and envelope tags remain unchanged.

The typed document API and authoritative Tally ENGINE_OPS contract expose both operations. The existing SheetTabs binding now supplies `onMove` and `onToneChange`, reads persisted tones and refreshes only after successful engine writes. Only these two deferrals were removed. Sheet duplication/protection, persisted charts/sparklines/views and the wider P13 exit remain open.

Static validation: `cargo check -p tally-engine` and `pnpm --filter @nitro-forge/tally typecheck` passed. No runtime, native or test execution was performed, in accordance with the review gate. Follow-up acceptance must cover both move directions, moving the active/inactive sheet, undo/redo mixed with existing cell/structural edits, invalid payload atomicity, legacy/current snapshot round trips and canonical native SheetTabs interaction. Existing fixture assumptions about deferred operations may require updating during that review. No component or phase acceptance is promoted.

Added source regression tests for active identity/cells, undo/redo, no-op empty event arrays and preserved history, invalid reorder atomicity, legacy snapshots and color round trips. Updated existing mock fixtures and canonical callback type contracts. These tests have not been executed.

The preview host now forwards onMove/onToneChange through its existing document write owner. The released alpha.4 SheetTabs retains positional rename drafts, so the host keys it to authoritative document revision/readiness: a reorder, restore or closed admission discards an old draft before a fresh callback can rename another positional sheet. This is a source ownership correction; keyboard/focus/runtime acceptance remains deferred.
