# P15 persistent PDF replies and author-specific review

Added Folio `addAnnotationReply`, `setAnnotationReview` and `listCommentThreads`, optional caller metadata on root annotation creation, typed APIs and gated canonical CommentsThreadPanel callbacks. These operations write actual lopdf annotation dictionaries and survive PDF save/reopen; they do not implement page rendering, cryptography or an authenticated identity service.

The primary [PDF 32000-1 specification](https://opensource.adobe.com/dc-acrobat-sdk-docs/standards/pdfstandards/pdf/PDF32000_2008.pdf), Table 170, defines same-page reply links and textual reply type. Section 12.5.6.3 describes author-specific state records and chaining later changes to the previous author's reply. Tables 172 and 165 define text-string state fields and the Hidden annotation flag. This implementation follows those structural rules; visual reader acceptance remains unverified.

Reply/review targets are primary Text/Highlight comments. Replies are Text annotations with /IRT, /RT /R and caller-supplied /T and /M. Review changes create separate Text state records with /StateModel Review and /State Completed or None, chaining to the prior selected author's state; root annotation state is untouched. State records use Hidden flag 2 and zero Rect so the newly created bookkeeping annotation is not instructed to display/print/interact. No appearance stream or visual rendering success is fabricated.

Author is nonblank text up to 256 UTF-8 bytes without control characters. Dates must be complete calendar-valid UTC PDF dates D:YYYYMMDDHHmmSSZ; no identity, clock or timezone is guessed. Partial/non-UTC imported dates are outside this admitted projection subset and reject rather than being silently normalized. Latest state is selected by validated UTC date and stable ObjectId tie-break. New changed review dates older than that author's latest reject before mutation; equal timestamps use the fresh object id. Same-state requests are eventless and preserve history.

Projection requires an explicit reviewAuthor. Completed means that author's resolved=true; None means false. Imported Accepted/Rejected/Cancelled values are retained as reviewState with resolved omitted. No all-authors/global resolution is inferred. State records are excluded from displayed body replies; nonempty state-record comment text, unknown state models, grouping replies and unsupported relationships reject conservatively. Existing author/time fields are preserved; an optional caller formatter supplies timeLabel from the actual stored date.

Graph validation checks cycles, dangling/unsupported/cross-page parents, /P consistency and unique page-array ownership, including roots without /P shared across two pages. Limits: 4096 annotation references per page, 10000 pages/100000 references for ownership scans, 100000 PDF objects, 256 records per thread and 64 reply links. Duplicate page object-number references reject. Replies cap at 32767 UTF-16 units. These limits do not establish process RSS or parser-security acceptance.

Deletion removes a bounded annotation descendant subtree in one undo step. A primary comment removes body replies and state chains; a reply removes its descendants. Generic page-owned Widget/Ink deletion remains supported and tested. External references, popup lifecycle relationships and unsupported imported graphs reject before mutation rather than leaving dangling objects. The external-reference scan caps at 1000000 visited values/depth64. Edits to comment text retain existing reply/metadata fields.

The adapter exposes reply/resolve only when the caller supplies metadata provider, reviewAuthor, isCurrent admission and commit(action) through its authoritative generation/document write gate. It checks admission around async work, rejects actor mismatch and unsupported mentions before document operations, rereads the thread inside the gate and checks again immediately before writing. No native expected-revision CAS is claimed; the caller owns serialization/generation. Delete uses that gate when supplied, while legacy no-context deletion retains its call shape. No application host is claimed activated by this source slice.

Verification: all 27 Folio crate tests passed, including seven new graph/metadata/state/PDF roundtrip tests; seven office adapter tests, one public payload-projection test and Folio TypeScript checks passed. Tests cover per-author projection, hidden state fields, Unicode body metadata, reply/state chaining, undo/redo, root/reply subtree deletion, real generic Widget/Ink import/removal, shared-root ownership, incoming/cyclic/dangling/cross-page graphs, bounds, object-id exhaustion, stale review dates, provider failure, actor mismatch and stale generation/thread admission. No native build or broad P19 matrix ran. Wider P15 work and component/phase acceptance remain open.

Independent review corrections: shared page-array ownership now rejects duplicated roots even without /P; imported generic Widget/Ink deletion is retained with safe external-reference rejection; public methods project only author/modified so extra provider profile fields cannot retarget operations. Provider metadata is copied before further awaits. These cases are covered by focused regressions.
