# P13 bounded COUNTIF and SUMIF evaluation

Added real COUNTIF/SUMIF processing to Tally's evaluator, with unchanged document/snapshot APIs and no new dependency or UI setting. Formulas stored in cells evaluate against actual cells, memoized dependencies and existing cycle/depth checks. A persisted-formula regression verifies recalculation after edits, undo/redo and reopening a snapshot.

Microsoft's [COUNTIF documentation](https://support.microsoft.com/en-us/excel/get-started/use-the-countif-function-in-microsoft-excel) documents conditional counting, comparison expressions, case-insensitive text and `*`/`?`/tilde wildcard syntax. Its [SUMIF documentation](https://support.microsoft.com/en-us/excel/functions/sumif-function) describes matching one range while summing another, optional sum_range, and Excel's resizing behavior for mismatched ranges. This implementation deliberately offers the narrower, explicit rules below rather than claiming Excel compatibility.

- Direct same-sheet cell/rectangular ranges only, at most 16384 cells each. SUMIF requires identical range dimensions and returns #VALUE! on mismatch. No implicit resized ranges, arrays, named ranges or cross-sheet references.
- Numeric criteria and numeric comparison strings use finite numbers and compare evaluated numeric values only. Numeric strings produced by formulas, Booleans and blank cells are not coerced into numbers. Boolean criteria match evaluated Booleans only.
- Text equality/inequality supports wildcards and escaped `~*`, `~?`, `~~`; other tildes remain literal. Matching ignores ASCII case while non-ASCII scalars compare exactly. `?` matches one original Unicode scalar, including supplementary characters; no normalization, Unicode casefold or locale collation is claimed. Relational nonnumeric text criteria return #VALUE!.
- Empty/empty-string criteria match empty cells and evaluated empty strings. `*` alone matches text, not empty cells. Comparisons do not cross value types beyond that explicit empty rule.
- Criteria expressions and encountered criteria-range errors/cycles propagate. SUMIF evaluates sum cells only for matched rows/columns, ignores matched nonnumeric values and propagates matched errors. Sum overflow returns #NUM!.

Criteria cap at 255 Unicode scalars; text matcher inputs cap at 4096 UTF-8 bytes, returning #VALUE! for violations. A shared per-Evaluator allowance of 1000000 conditional scan/string/DP steps returns #NUM! when exhausted. Work is charged before bounded matcher buffers are allocated and for each DP transition; no recursive/backtracking wildcard matcher is used. These work limits do not claim a measured process-memory bound or change unrelated evaluator functions.

Focused tests cover numeric/reference/concatenated criteria, evaluated numbers vs strings, Booleans, blanks, Unicode scalar wildcards, ASCII case, literal wildcard escapes, shape/reference/arity errors, criteria errors/cycles, lazy sum-cell evaluation, overflow, range/string/shared-work limits, and actual stored formula persistence/history. All 49 affected Tally engine tests passed, including five new conditional tests; Tally TypeScript checks passed. No native build or broad P19 suite ran. Wider P13 functionality and acceptance remain open.
