# P11 Motion: owned immutable RGBA asset source

Motion now owns decoded packed `rgba8-straight-srgb` assets and layers that reference stable asset IDs. Every layer contains exactly one legacy shape or real raster reference. Asset pixels cannot be edited in place; replacement pixels create a new identity. Referenced assets cannot be removed. Old shape snapshots default the asset table/counter and remain readable inside unchanged schema1/NFD1 framing.

Native ingestion moves the existing owned Command.input vector; JSON input uses bounded canonical base64. Dimensions/encoded length/padding/alphabet and decoded aggregate are preflighted before pixel allocation; canonical bytes/exact length, asset references and complete candidate state validate before publication. Snapshot decode checks aggregate declared sizes before any raster decoding. Asset storage uses immutable Arc buffers, shared across layers/history/header changes; raw reads return owned copies. The typed facade immediately copies the exact Uint8Array/Buffer subview and encodes before any await, with no public optional-host shim or borrowed caller buffer.

Prism owns real rendering: addRasterLayer and binary drawPixels upload materialize the asset, followed by the existing pivoted transforms, opacity, visibility and scalar-keyframe evaluation. Original RGB values under alpha 0 remain in the asset while compositing produces actual transparent output. Fully transparent assets render with identity and nonzero pivot/mirrored/rotated transforms. No placeholder shape, image decoder, resampling provider, ICC conversion, video decoder or encoded queue is supplied.

Logical limits: positive dimensions at most 4096 and one megapixel per asset; 16 assets; 4 MiB decoded total; 16 raster layers and current canvas backing count×compositionWidth×compositionHeight×4 at most 16 MiB. Because Prism raster backing is composition-sized, referenced asset dimensions must fit the composition; incompatible layer creation/resize rejects atomically rather than clipping pixels silently. The compositor's temporary journal can retain previous canvases/regions, so these are current-storage bounds, not measured peak RSS. Existing 16-entry history and 16 MiB serialized-state limits remain.
