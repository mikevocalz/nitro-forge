# P16/P17 backend entry plan

Initial source audit, 2026-11-07. At audit time, neither design nor CAD documents were registered. The subsequent Design9 fixed-frame source checkpoint now implements the first bounded layout/render slice; see [source and checks](P16-design-fixed-frame-source.md). The subsequent [Draft10 source](P17-draft-source.md) implements bounded world points/segments, real snaps, linear coordinate solving and actual Prism rendering. Full design and CAD/3D scope remains open. Canonical controls exist in NYC-Tron `packages/ui/src/components/forge/design/` and `cad/`; they supply callback contracts, not a layout/geometry backend.

## Shared production foundation

Follow `packages/motion/rust/src/lib.rs` and `packages/photo/rust/src/lib.rs`: explicit kind/schema snapshots, safe monotonic IDs, bounded candidate validation, eventless no-ops, atomic batches and owned Arc history. Use `DocumentHandle.openSnapshot` for borrowed-byte ownership. A new kind needs Rust EngineKind/CLI/FFI/C++ factory, TS unions, generated Nitro enum, distinct appended NFC1/NCC1 tags and isolated workspace lock importer. The parent assigns additive ordinals after checking existing registrations; preserve every earlier ordinal. Older binaries must reject unsupported kinds honestly; rebuilt native consumers remain a gate.

Prism is available without a new dependency: `packages/prism/rust/{Cargo.toml,src/model.rs,src/geom.rs,src/vector.rs,src/render.rs}` provide actual shapes, paths/strokes, affine math and RGBA compositing. Motion demonstrates ephemeral Prism scene rendering and JSON/binary output. `packages/studio-layout/src/index.ts` is application dock geometry, not document auto layout. No geometry solver or design-layout dependency was found in inspected Cargo dependencies; this audit selects none.

## P16 first vertical slice: fixed/flow frames to real pixels

Proposed `packages/design/rust/src/{lib,model,layout,render}.rs` plus typed `src/index.ts` should own an acyclic ordered frame/rect/ellipse tree, parent references, local geometry, visibility/lock, axis sizing and layout settings. Start with fixed-size root frames and fixed children; add row/column gap, four paddings, cross alignment and main distribution with an actual deterministic box evaluator. Proposed ops: `new`, `addFrame`, `addShape`, `updateNode`, `reparentNode`, `setChildOrder`, `setFrameLayout`, `setAxisSizing`, `evaluateLayout`, `renderFrame`, `describe`. Validate the entire proposed hierarchy before mutation, including depth/count/size/output limits, no cycles and locked edits. Render evaluated boxes through Prism and test actual RGBA plus save/reopen and failed-layout atomicity.

Then implement intrinsic bottom-up hug and definite-parent fill, with explicit rejection of cyclic hug/fill dependencies; wrap needs real line breaking and cross-line sizing before exposing it. Canonical `AutoLayoutInspector` always presents wrap/alignment/justify, so do not mount a partially supported inspector and silently ignore fields. `HugFillFixedSizeControls` exposes canHug/canFill and reasons: derive these from evaluator capabilities. `ConstraintsPanel` has anchor/stretch/scale/aspect/min-max/relative target fields; defer this panel until all admitted modes have reference geometry and deterministic resize semantics. Tree controls may precede these panels only when each advertised action has an authoritative operation.

Later independent slices: component definitions/instances/variant resolution; typed variables/modes and cycle-free alias evaluation; persisted prototype graph plus real trigger/navigation runtime; actual comment/presence service integration; encoded multi-slice export. Primitive RGBA layout does not establish text metrics, clipping, prototype execution or these services.

## P17 first vertical slice: real bounded 2D drafting

Proposed `packages/draft/rust/src/{lib,geometry,snaps,constraints,render}.rs` should own units, stable points/segments/circles, layer/order/lock and typed constraint references. Proposed ops: `addPoint`, `addSegment`, `addCircle`, `updateEntity`, `removeEntity`, `setSnapSettings`, `querySnap`, `addConstraint`, `updateConstraint`, `removeConstraint`, `solve`, `evaluate`, `renderFrame`. Geometry is authoritative world-space data; screen transform and selection remain host view state.

Implement actual grid, endpoint, midpoint, center, finite-segment intersection/projection, ortho and polar calculations with finite tolerances, deterministic tie-breaking and source revision. Return true world coordinates and distance for `ObjectSnapsAndOrtho`; convert a screen-pixel tolerance through the current invertible viewport transform. Avoid claiming snap availability from stored booleans alone. Map `DraftingCommandLine` through a bounded explicit parser for supported commands into the same operations; reject unsupported commands, retain failed drafts, never eval expressions as code.

A smallest real constraint slice can solve only linear point-coordinate constraints: fixed coordinates, coincidence, horizontal/vertical alignment and signed horizontal/vertical distances. Build a bounded linear system, rank/consistency checks and deterministic free-variable policy retaining unconstrained coordinates. Return actual residuals, rank-derived degrees of freedom and conflict evidence; do not claim minimal conflict sets without an implemented search. Commit solved geometry atomically only after residual validation. `ParametricConstraintEditor` supports canCreate/readOnly and solver status/DOF/conflicts: expose only implemented typed kinds, with a bounded expression grammar or read-only generated expressions. Euclidean distance, angle/tangent/equal-radius and general nonlinear solving are later backend work, not placeholder success states.

Render real segments/circles through Prism paths/strokes and test coordinate/snapping/constraint fixtures plus pixels, undo, corrupt restore and resource limits. Add dimensions as measured derived geometry before paper-space plotting/encoding. Native3DViewport, gizmos, UV/PBR/projected brushes, baking and node evaluation require actual admitted scene/renderer/geometry execution; a 2D drafting document closes none of those capabilities.

## Host and acceptance gates

Wire only released canonical subpaths with authoritative document/revision admission, observed promise failures and Zustand selection. Use real output surfaces, exact viewport-to-world transforms and cancellation before publishing asynchronous results. Preserve app window dimensions/orientation and native configuration. Scoped model/math/pixel/persistence tests should accompany each bounded slice; native ABI, accessibility/input, performance and platform acceptance require separate executed evidence. No P16/P17 component or phase acceptance is promoted by this plan.
