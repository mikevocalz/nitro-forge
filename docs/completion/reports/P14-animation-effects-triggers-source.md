# P14 real animation effects and explicit trigger evaluation

Pitch now evaluates pulse, spin, fadeOut and zoomOut alongside its existing entrance effects. Pulse center-scales 1→1.2→1 with a triangular progress curve; spin adds 360p degrees; fadeOut multiplies opacity by 1−p; zoomOut center-scales 1→0.5 and multiplies opacity by 1−p. Geometry and opacity actually change in slideAt output, rather than storing unused settings. Repeated-object effects compose in declaration order: opacity multiplies and geometry changes sequentially. Pending entrance contributions remain at their initial hidden/offset state; pending exit/emphasis contributions are neutral. This is an explicit supported evaluator, not full PowerPoint semantics or an easing catalog.

Animations persist a tagged trigger: absolute (legacy default), on-click with explicit click_index, with-previous, or after-previous. For nonabsolute triggers start_s is delay. Click mode uses the corresponding host-supplied slide-relative timestamp; relatives use the immediately preceding list entry's resolved start/end. Missing click input remains null/pending and propagates through dependent entries. The engine never creates a click event, presentation timer or timestamp. Host histories must be a finite ordered prefix of at most 256 timestamps, each 0..86400 seconds; trigger shapes/click indices are validated before cloning. Typed APIs own trigger data and click arrays before transport awaits.

Object/animation work caps at 4096 per slide and resolved timelines at 86400 seconds. Referenced objects and unique identities validate; nonfinite composed geometry/opacity rejects instead of producing invalid JSON. Updates, animation removal and object cleanup validate complete candidate timelines before journaling. Removing a predecessor that leaves a first relative effect rejects atomically; other relative entries deliberately reanchor to their previous surviving list entry. Missing snapshot triggers preserve legacy absolute timing within the declared bounds, and defaults remain omitted from encoding. Read-only evaluation preserves history; failed restore leaves state/history intact.

The installed pinned alpha.4 SlideAnimationPane declarations were inspected directly. They provide effect/add/remove callbacks but lack timing/order/trigger edit callbacks. Its adapter now offers the seven effects the evaluator plays. Nonabsolute trigger metadata is retained for host use, but binding the old pane over such a program rejects rather than presenting relative delays as absolute starts. No new callback or fake preview playback was invented. The engine API and readPitchSlideAt accept explicit click input independently; no application host activation is claimed.

Verification: all 34 Pitch engine tests pass, including nine new effect/timeline/history/bounds regressions. The actual pixel regression feeds resolved exit geometry/opacity through the existing Prism CPU renderer via CLI: pending, midpoint and completed exit produce red RGBA [255,0,0,255], [255,0,0,128] and transparent [0,0,0,0], with midpoint pixels preserved after Pitch snapshot/reopen. This verifies real existing-renderer integration, not a new Pitch renderer. All 24 Pitch TypeScript tests pass across six files. Adapter/ownership tests cover supported effects, old-pin capability refusal and copied click/trigger inputs. Pitch TypeScript checks and the CLI source build pass with CARGO_INCREMENTAL=0.

No dependency, native application build, release/pin, engine identifier or platform window contract changed. P14 still needs host presentation clock/click collection, native/media/rendering acceptance and its remaining authoring/presenter features. No component or phase acceptance is promoted.

Review closure: every persisted program validates its earliest possible click schedule using zero timestamps before mutation or restore; a later actual host click may still exceed the bound and reject read-only evaluation. Object adds preflight the 4096 capacity before journaling. Allocation and restore enforce globally unique positive slide/object identities and a monotonic counter within the JavaScript safe integer range; exhaustion rejects before history or state changes. Focused regressions preserve snapshot/history/redo across rejected timelines, capacity and identity inputs.

Mixed-version transport: explicit trigger and click intent route through versioned operation aliases, making old engines reject unknown operations rather than silently executing absolute timing. Omitted optional arguments retain legacy operation names. Rust alias equivalence and a deliberately old host rejection regression cover this boundary. Snapshot compatibility is handled separately below. P20 activation still requires matching reader/writer/runtime admission; no native/public pin activation is claimed.

Snapshot closure: nondefault size, section records or advanced section counter, nonabsolute triggers and new effects select the Pitch-local kind/schema2/document JSON wrapper inside unchanged framing/tags. Root meta is deliberately absent, so the legacy required-root parser rejects it. Legacy-feature-only output stays unwrapped; current restore accepts both and strictly rejects foreign kinds, unsupported schema or extra wrapper keys before replacement. A focused actual snapshot/reopen and legacy-root rejection regression covers each feature class. P20 matching-runtime admission remains required; no native activation is claimed.
