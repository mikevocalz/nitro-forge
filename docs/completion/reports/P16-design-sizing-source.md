# P16 Design intrinsic and fill sizing checkpoint

Adds durable optional x/y fixed/hug/fill modes, actual bounded dependency evaluation, setAxisSizing and readAxisSizing capability operations. Old nodes default to both fixed and omit that field when serialized. The root stays a fixed document canvas; no app window or registration changes occur.

Frame hug derives real child extents, flow gaps/padding and wrapped line cross sizes. Empty hug content has a 0.001 minimum, so deleting the last child works. Absolute hug preserves its origin and measures positive trailing extents; negative leading children remain visible overflow. Fill uses definite parent content: equal remaining main shares in nonwrap flow, full cross content, or remaining absolute extent after local offset. Descendant fill uses effective stretched ancestor dimensions. Cycles, nonpositive fill space, wrapped main-axis hug, fill children directly inside wrapped flow, primitive hug and cross hug under parent stretch reject with actual capability reasons. Wrapped cross hug works with fixed intrinsic stretch children. Candidate/render bounds include all hidden nodes and effective padding.

Capability reads clone and evaluate proposed modes without modifying history. They return canHug/canFill and per-mode reasons, actual resolvedValue and retained fixedValue. Root/locked ancestry supplies unavailableReason. Width/height remain authored fallback during hug/fill; direct numeric extent edits require fixed mode. A fixed transition with omitted value freezes evaluated size, while explicit fixed value intentionally resizes. The typed method projects only writable fields and preserves authoritative target/axis and awaited errors. Fixed dimensions now share the renderer 1e7 ceiling (positions 1e6, root 4096/one-megapixel unchanged), so a valid large intrinsic size can freeze without jumping or trapping. Canonical source numeric controls still cap fixed input at 1e6; that range alignment and any control/pin activation remain future integration gates.
