# Draft: bounded 2D backend

Draft persists world points, ordered segments and analytic circles/arcs, calculates actual world snaps, and solves fixed/coincident/horizontal/vertical/signed-axis-distance linear constraints. Rank, DOF, residual and unsatisfied IDs describe the admitted matrix. Inconsistent or out-of-bounds geometry never publishes; locked coordinates remain exact.

Anchor-based ortho axes and legal polar rays are computed in world space with explicit tolerance. A bounded POINT/LINE/SEGMENT/CIRCLE/ARC/MOVE/DELETE/SOLVE/SNAP grammar reuses the same atomic engine operations; unsupported commands reject without mutation. Canonical source-shaped bindings preserve failed drafts and withhold stale revision-tagged snap feedback. These CAD controls are not in the pinned alpha.4 exports, so this source does not activate them.

It renders actual Prism stroked-path RGBA through a supplied world viewport. Distinct coincident points are valid and their zero-length segment draws no path. Endpoints include all authored points; other snaps use visible finite segments and circular entities. Circle/arc closest points, centers, tangent contacts and unique intersections use analytic world math. Curves display through at most four cubic spans in Prism, an approximation for display rather than precision plotting. Radius/angles are authored values outside the point-coordinate linear solver. Collinear/nonunique and angular-nearparallel intersections are excluded. Exact limits and semantics are in ENGINE_OPS and the P17 source report.

`findProfiles` is a read-only deterministic closed-loop tracer over visible segments and arcs: endpoint coincidence within a world-unit tolerance (implicit hop chords keep area/centroid integrals exact over the closed polygon), analytic area/centroid/bounds, nested-loop grouping and document-order sorting, with no journal or events.

Kind/native/checkpoint tag 10 appends after Design 9. NFD1 framing stays unchanged. Snapshots retain original legacy bytes without new features; circular geometry/new enabled snap modes require a strict Draft/schema2 JSON wrapper so old readers fail safely. Both forms use validated internal state and shared borrowed-byte ownership. No default UI, native target acceptance, general nonlinear/3D CAD, encoded delivery or complete P17 acceptance is implied.
